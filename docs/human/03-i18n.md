# i18n (host side)

This guide covers i18n from the app developer's point of view: host
messages and locale switching. If you are authoring a component that
translates its own strings, see
[Authoring Components](05-authoring-components.md).

## Host messages

The host owns the app-level strings. They live in
`apps/demo/src/locales/demo.json`:

```json
{
  "en": {
    "nav": { "dashboard": "Dashboard" }
  },
  "zh-CN": {
    "nav": { "dashboard": "仪表盘" }
  }
}
```

The framework uses vue-i18n. The app creates a global composer:

```ts
// apps/demo/src/i18n.ts
import { createI18n } from "vue-i18n";

export const i18n = createI18n({
  legacy: false,
  locale: "en",
  fallbackLocale: "en",
  missingWarn: false,
  fallbackWarn: false,
});
```

## How locale messages reach the shell

`AdminProvider` seeds the host messages into the global composer at setup
time. The shell reads the active locale from the preferences store and
synchronizes the composer.

Menu labels, tab labels, and page content translate through the global
composer:

```ts
i18n.global.t("nav.dashboard")
```

## Choosing the locale

The shell preferences control switches the active locale. The demo ships
`en` and `zh-CN`.
