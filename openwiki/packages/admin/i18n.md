# Admin i18n — Locale Typing and Resources

The admin package's i18n surface is derived from the framework-wide override
registry in `@noob-naive-ui/registry` (see [registry package](../registry.md)
and [i18n package](../i18n.md)); this module only pins the admin locale schema
and library key.

## Library key (`src/registry.ts`)

```ts
export const LIB_ID = "noob-naive-ui:admin" as const;
```

- `LIB_ID` (in `registry.ts`, not a separate i18n module) is the admin package's
  **stable library key** under which hosts provide admin overrides in the shared
  registry (via the `AdminProvider` `i18nOverrides` prop — see
  [Root Provider](provider.md)). The admin `LibraryOverridesRegistry` module
  augmentation (in `registry.ts`) declares the FULL admin locale schema, so
  `createComponentI18n` derives it from this key alone — **there is no separate
  descriptor handle**.
- **There is no Vue plugin and no separate i18n key anymore**: the former
  `adminI18nPlugin`, `adminI18nOverridesKey`, `DEFAULT_SNAPSHOT`,
  `AdminI18nPluginOptions`, and the `adminI18n`/`AdminI18nSnapshot` exports were
  removed. The shared `libraryOverridesKey` + `emptySnapshot` replace the
  per-package key and default snapshot; `tests/i18n-contract.test.tsx` asserts
  the removed `adminI18nPlugin` no longer exists ("no longer exposes the removed
  adminI18nPlugin"). Components call `createComponentI18n` with
  `libraryId: LIB_ID` directly (`admin-shell.tsx` uses `"noob-naive-ui:admin"`).
- The barrel (`src/index.ts`) re-exports the `AdminLocale`-family **types** from
  `./i18n`; the `LIB_ID` constant is **module-internal** (components import it
  directly; hosts address the registry slice by string key).

## Locale typing (`src/i18n.ts` — single module, no subdirectory)

```ts
export type AdminLocaleName = "en" | "zh-CN";
export type AdminShellLocale = LocaleFileMap["AdminShell"]["en"];
export type AdminLoginPageLocale = LocaleFileMap["AdminLoginPage"]["en"];
export interface AdminLocale { AdminShell: AdminShellLocale; AdminLoginPage: AdminLoginPageLocale; }
export type AdminLocaleOverrides = NonNullable<
  RegistryI18nOverrides["noob-naive-ui:admin"]
>;
```

- Message-shape types come from the **generated** `src/locales/locale-types.generated.ts`
  (`LocaleFileMap`), produced from the JSON resources by
  `tooling/vite/json-locale-types` at build start; packaged messages and the
  public override contract therefore cannot drift.
- The generated module lives under `src/` so the declaration build emits
  `dist/locales/locale-types.generated.d.ts` and exported types stay resolvable
  for consumers without JSON references in published declarations.
- `AdminLocaleOverrides` is the registry's i18n projection of the admin
  augmentation — a locale-first, per-component, deeply-optional partial tree;
  hosts override only the message leaves they own. The partial-tree machinery
  lives in exactly one place (the registry), not in a hand-written override type.

## Locale resources

- `src/locales/AdminShell.json` — en/zh-CN messages for the shell:
  `account.signOut`, `fontSize.{small,medium,large}`, `aria.*` labels,
  `tabs.openPages`, `errors.{unableToNavigate,unableToCloseTab}`, `signedIn`.
- `src/locales/AdminLoginPage.json` — en/zh-CN messages for the login page:
  `loading.*`, `alreadySignedIn.*`, `status.{expired,forbidden,signedOut,unknown}`,
  `form.*` (signIn, username, password, rememberMe, signingIn).

## Host override recipe

The only override path is the `i18nOverrides` prop on `AdminProvider`
([Root Provider](provider.md)): it carries the whole registry's i18n projection
keyed by libraryId, and `AdminProvider` passes the admin slice to
`AdminConfigProvider`, which provides it under `libraryOverridesKey` (merged over
any parent registry value, so the nearest provider wins).

```tsx
<AdminProvider
  messages={demoMessages}
  menu={demoMenu}
  i18nOverrides={{
    "noob-naive-ui:admin": {
      en: { AdminShell: { account: { signOut: "Log out" } } },
      "zh-CN": { AdminShell: { account: { signOut: "退出" } } },
    } satisfies AdminLocaleOverrides,
  }}
/>
```

The registry value is deliberately loose at the provider boundary (`unknown`
per entry); hosts pin each entry with `satisfies <Package>Overrides` and the
registry's derived projections type the slice at consumption. The admin entry is
proven by `tests/admin-provider.test.tsx` ("provides the admin text-override
snapshot to descendants via the overrides key") and `tests/i18n-contract.test.tsx`
(snapshot defensive copy, slice selection, merge-after-defaults).

The override slice is merged after packaged defaults in
`createComponentI18n`, so overrides win at the leaf while siblings survive —
covered by `tests/i18n-contract.test.tsx` ("merges a partial override after
defaults without losing siblings") and the i18n package's own tests.

## Tests

`packages/admin/tests/i18n-contract.test.tsx` (6 `it`):
- snapshots caller overrides when provided through the `i18nOverrides` prop
  (defensive copy — the merged registry value is a fresh object);
- selects only the requested component slices by locale;
- asserts the removed `adminI18nPlugin` is no longer exposed;
- merges a partial override after defaults without losing siblings;
- renders the packaged zh-CN defaults when the host locale is zh-CN;
- keeps an unsupported active locale while rendering the host fallback.
