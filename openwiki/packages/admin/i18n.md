# Admin i18n — Descriptor, Locale Typing, and Resources

The admin package's i18n surface is produced from the shared registry primitives
in `@noob-naive-ui/i18n` (see [i18n package](../i18n.md)); this module only pins
the admin locale schema.

## i18n descriptor (`src/i18n/plugin.ts`)

```ts
import type {
  LibraryI18nDescriptor,
  LibraryI18nSnapshot,
} from "@noob-naive-ui/i18n";
import type { AdminLocale, AdminLocaleName } from "./admin-locale";

export const adminI18n: LibraryI18nDescriptor<AdminLocaleName, AdminLocale> = {
  libraryId: "noob-naive-ui:admin",
};
export type AdminI18nSnapshot = LibraryI18nSnapshot<AdminLocaleName, AdminLocale>;
```

- The runtime value is only the stable `libraryId` under which hosts provide
  admin overrides in the **shared registry** (via the `AdminProvider`
  `overrides` prop — see [Root Provider](provider.md)); the generic parameters
  pin the admin locale schema for `createComponentI18n`.
- **There is no Vue plugin anymore**: `adminI18nPlugin`, `adminI18nOverridesKey`,
  `DEFAULT_SNAPSHOT`, and `AdminI18nPluginOptions` were removed in the
  override-registry refactor (08-13). The shared
  `libraryI18nOverridesKey` + `emptySnapshot` from `@noob-naive-ui/i18n` replace
  the per-package key and default snapshot; `tests/i18n-contract.test.tsx`
  asserts `adminI18nPlugin` no longer exists ("no longer exposes the removed
  adminI18nPlugin").
- The barrel (`src/index.ts`) re-exports only the `AdminI18nSnapshot` type;
  `adminI18n` itself stays module-internal (components import it directly).

## Locale typing (`src/i18n/admin-locale.ts`)

```ts
export type AdminLocaleName = "en" | "zh-CN";
export type AdminComponentId = "AdminShell" | "AdminLoginPage";
export type AdminShellLocale = LocaleFileMap["AdminShell"]["en"];
export type AdminLoginPageLocale = LocaleFileMap["AdminLoginPage"]["en"];
export interface AdminLocale { AdminShell: AdminShellLocale; AdminLoginPage: AdminLoginPageLocale; }
export type AdminLocaleOverrides = LibraryI18nOverrides<AdminLocaleName, AdminLocale>;
```

- Message-shape types come from the **generated** `src/locales/locale-types.generated.ts`
  (`LocaleFileMap`), produced from the JSON resources by
  `tooling/vite/json-locale-types` at build start; packaged messages and the
  public override contract therefore cannot drift.
- The generated module lives under `src/` so the declaration build emits
  `dist/locales/locale-types.generated.d.ts` and exported types stay resolvable
  for consumers without JSON references in published declarations.
- `AdminLocaleOverrides` is a locale-first, per-component, deeply-optional
  partial tree; hosts override only the message leaves they own.

## Locale resources

- `src/locales/AdminShell.json` — en/zh-CN messages for the shell:
  `account.signOut`, `fontSize.{small,medium,large}`, `aria.*` labels,
  `tabs.openPages`, `errors.{unableToNavigate,unableToCloseTab}`, `signedIn`.
- `src/locales/AdminLoginPage.json` — en/zh-CN messages for the login page:
  `loading.*`, `alreadySignedIn.*`, `status.{expired,forbidden,signedOut,unknown}`,
  `form.*` (signIn, username, password, rememberMe, signingIn).

## Host override recipe

The only override path is the `overrides` prop on `AdminProvider`
([Root Provider](provider.md)): it provides the whole shared registry under
`libraryI18nOverridesKey`, keyed by libraryId, and each entry is
`structuredClone`d at provide time so later caller mutation cannot leak in.

```tsx
<AdminProvider
  messages={demoMessages}
  menu={demoMenu}
  overrides={{
    "noob-naive-ui:admin": {
      en: { AdminShell: { account: { signOut: "Log out" } } },
      "zh-CN": { AdminShell: { account: { signOut: "退出" } } },
    } satisfies AdminLocaleOverrides,
  }}
/>
```

The registry value is deliberately loose at the provider boundary (`unknown`);
hosts pin each entry with `satisfies <Package>Overrides` and the descriptor's
selector types the slice at consumption. The admin entry is proven by
`tests/admin-provider.test.tsx` ("provides the admin text-override snapshot to
descendants via the overrides key") and `tests/i18n-contract.test.tsx` (snapshot
defensive copy, slice selection, merge-after-defaults).

The override slice is merged after packaged defaults in
`createComponentI18n`, so overrides win at the leaf while siblings survive —
covered by `tests/i18n-contract.test.tsx` ("merges a partial override after
defaults without losing siblings") and the i18n package's own tests.

## Tests

`packages/admin/tests/i18n-contract.test.tsx` (6 `it`):
- snapshots caller overrides when provided through the `AdminProvider`
  `overrides` prop (defensive copy);
- selects only the requested component slices by locale;
- asserts the removed `adminI18nPlugin` is no longer exposed;
- merges a partial override after defaults without losing siblings;
- renders the packaged zh-CN defaults when the host locale is zh-CN;
- keeps an unsupported active locale while rendering the host fallback.
