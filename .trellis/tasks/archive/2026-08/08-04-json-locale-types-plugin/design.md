# Design: Generic JSON→TS locale type generator

## 1. Module: `tooling/vite/json-locale-types.ts`

Zero-dependency shared module (node builtins + `vite` type-only imports),
matching the existing `tooling/vite/vue-i18n.ts` convention. Exports:

```ts
export interface JsonLocaleTypeFile { name: string; content: unknown }

export interface GenerateJsonLocaleTypesOptions {
  /** Maps a relative stem to the emitted type name (default: PascalCase of path segments). */
  typeName?: (stem: string) => string;
  /** Name of the emitted file-stem → type map (default "LocaleFileMap"). */
  mapName?: string;
  /** Directory label embedded in the stable header (relative paths only). */
  sourceDir?: string;
}

export interface CreateJsonLocaleTypesPluginOptions {
  /** Absolute directory scanned recursively for `*.json` files. */
  dir: string;
  /** Absolute output path of the generated TS module. */
  outFile: string;
  typeName?: (stem: string) => string;
  mapName?: string;
}

/** Pure core: JSON payloads → generated TS module source. Testable. */
export function generateJsonLocaleTypes(
  files: JsonLocaleTypeFile[],
  options?: GenerateJsonLocaleTypesOptions,
): string

/** Recursive, sorted `*.json` scan (exported for tests/drift guard). */
export function scanJsonLocaleFiles(dir: string): JsonLocaleTypeFile[]

/** Regenerates `outFile` from `dir`; true when it changed. Testable. */
export function regenerateLocaleTypes(
  dir: string,
  outFile: string,
  options?: { typeName?: (stem: string) => string; mapName?: string },
): boolean

/** Vite plugin: scans `dir`, regenerates `outFile` on buildStart and on
 * locale JSON changes during dev (`watchChange`, guarded against the
 * output file itself and mid-save parse errors). */
export function createJsonLocaleTypesPlugin(
  options: CreateJsonLocaleTypesPluginOptions,
): Plugin
```

API deviation from the draft: `dir` (recursive scan) instead of a glob —
matches the "point at a directory" requirement and keeps the module
zero-dependency; nested objects emit as indented inline object types (not
named interfaces), avoiding nested-name collisions; array element types are
sorted for deterministic output.

## 2. Type emission semantics

Mirror `resolveJsonModule` inference exactly (so a future
`Equals<AdminShellLocale, typeof jsonImport>` guard would hold):

| JSON value | Emitted type |
|---|---|
| string | `string` |
| number | `number` |
| boolean | `boolean` |
| null | `null` |
| object | indented inline object type (keys quoted when not identifiers, e.g. `"zh-CN"`) |
| array | sorted element union: `(A \| B)[]`, `A[]`, `never[]` for `[]` |

Top-level per file: `export interface <TypeName> { … }`. Then:

```ts
export interface LocaleFileMap {
  AdminShell: AdminShell;
  AdminLoginPage: AdminLoginPage;
}
```

Generated file header: `// Auto-generated by tooling/vite/json-locale-types. DO NOT EDIT.` plus the source glob and timestamp? (no timestamp — output stability; glob only).

Name handling: stem → PascalCase (`foo-bar` → `FooBar`, `admin_login` →
`AdminLogin`), sanitized to `[A-Za-z0-9_$]`; collisions between stems →
throw with the colliding stems (config error, not silent).

## 3. Vite plugin mechanics

- `buildStart`: resolve `include` globs against the workspace root (module
  dirname `../..`, same as the preset), read each JSON (`JSON.parse`; parse
  failure → build error naming the file), run the pure generator, write
  `outFile` (mkdir -p). Runs before the module graph is processed, so
  `unplugin-dts` sees the fresh file; registered first in the admin plugin
  array.
- Always regenerates (v1). A strict/`--check` drift mode is a documented
  follow-up (compare generated vs on-disk, fail with regenerate guidance).
- The generated file is committed; `tsc --noEmit` (CI) reads it directly —
  no vite needed.

## 4. Admin wiring

`packages/admin/vite.config.ts`:

```ts
import { createJsonLocaleTypesPlugin } from "../../tooling/vite/json-locale-types";

plugins: [
  createJsonLocaleTypesPlugin({
    include: resolve(__dirname, "src/locales/**/*.json"),
    outFile: resolve(__dirname, "src/locales/locale-types.generated.ts"),
  }),
  vueJsx(),
  dts({ tsconfigPath: "./tsconfig.build.json" }),
  // …
],
```

`packages/admin/src/i18n/admin-locale.ts` (after):

```ts
import type { LocaleFileMap } from "../locales/locale-types.generated";

export type AdminLocaleName = "en" | "zh-CN";
export type AdminComponentId = "AdminShell" | "AdminLoginPage";

/** Derived from the packaged AdminShell messages (en subtree). */
export type AdminShellLocale = LocaleFileMap["AdminShell"]["en"];
/** Derived from the packaged AdminLoginPage messages (en subtree). */
export type AdminLoginPageLocale = LocaleFileMap["AdminLoginPage"]["en"];

export interface AdminLocale {
  AdminShell: AdminShellLocale;
  AdminLoginPage: AdminLoginPageLocale;
}

export type AdminLocaleOverrides = Partial<
  Record<AdminLocaleName, DeepPartial<AdminLocale>>
>;

type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};
```

Indexing the `en` subtree matches the manual interfaces' widened shape;
cross-locale divergence follows en (same caveat as today — the overrides
contract is shape-only).

## 5. Declaration/packaging path

`locale-types.generated.ts` is under `src/` → included by
`tsconfig.build.json` (`src/**/*.ts`) → `unplugin-dts` emits
`dist/locales/locale-types.generated.d.ts` (+ map) → `admin-locale.d.ts`
emits `import type { LocaleFileMap } from "../locales/locale-types.generated"`
→ resolvable sibling d.ts (the exact pattern verified in the TS-resource
experiment). Dist gains two small declaration files; runtime bundle
unchanged (type-only module erased).

## 6. Tests

New `packages/admin/tests/json-locale-types.test.ts` (the tooling module
has no test runner; tested through the admin suite via relative import of
the pure `generateJsonLocaleTypes`):

- nested object → nested interfaces; `"zh-CN"`-style quoted keys
- primitives (string/number/boolean/null)
- arrays: uniform → `X[]`, mixed → `(A | B)[]`, empty → `never[]`
- naming: `foo-bar.json` → `FooBar`; collision (`a-b.json` + `a_b.json`) → throws
- map emission with default and custom `mapName`
- output stability: same input → identical output (no timestamps)
- the committed generated file matches a fresh generation (drift guard)

## 7. Risks

1. **JSON parse error in a locale file** → hard build error naming the file
   (by design; JSON is the contract).
2. **`unplugin-dts` ordering** — plugin writes in `buildStart`, before the
   module graph/dts program; registered first in the plugin array.
3. **Interface-key quoting** — `"zh-CN"` must round-trip as a quoted
   identifier; covered by tests.
4. **`["en"]` subtree index** — `LocaleFileMap["AdminShell"]` is the whole
   locale-first file type; `["en"]` is the per-locale subtree. If a future
   locale diverges in shape, the derived type follows en (documented).
